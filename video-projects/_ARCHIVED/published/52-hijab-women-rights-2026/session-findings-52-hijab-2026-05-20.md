## 2. Findings (ranked by severity / leverage)

### Finding 1 — Scopic regime attribution error in finished cut [HIGH — shipped to live video]

Script at ~01:02:19 attributes "scopic regime" to "Historian Lloyd Jones" (Lloyd Llewellyn-Jones). Filmed in audio. Now live.

**Actual attribution per project NotebookLM notebook (`322e3b05-5960-4036-8dac-02e2377db07c`, queried 2026-05-20):** "scopic regime" originates with Christian Metz (French film theorist), via Martin Jay, brought into Islamic studies by **Aisha Geissinger** (*Gender and Muslim Constructions of Exegetical Authority*, Brill 2015, p. 216, fn. 25). Llewellyn-Jones's actual coinage is "**portable seclusion**" — a different concept (the veil as wearable home / spatial technology, *Aphrodite's Tortoise* p. 5).

The interesting wrinkle: the verbatim *definition* in the script ("a system in which visibility itself functions as a social regulation") was correctly verified against Geissinger's text. The text was right; the byline was wrong. This is a new error class:

> **Verbatim verification ≠ attribution verification.**
> Round-tripping a quote through NotebookLM confirms "did this text appear." It does NOT confirm "did THIS scholar originate it." When a scholar quotes / borrows / paraphrases another scholar, attribution slips past quote-grounding even when the quote itself is clean.

**This is the 5th ground-claim primary failure on this project alone**, joining: Tabari defense quote (paraphrase tagged to Tabari Vol 19); Musannaf Ibn Abi Shayba p. 135 (wrong edition); Hafsa bint Sirin transmitter chain (Bewley shows Sawda → Khawla bint Qays); §V "distinction which Sharia intended" (Grok-fabricated Arabic, primary not located).

**Detection point:** Opus planning pass for `06-METADATA-EXECUTION-PLAN.md`, 2026-05-20 — two days post-filming, video already published.

**Remediation chosen:** Pinned correction comment (default per execution plan §A2 — option B). Lower cost than re-cut; aligns with channel's transparency positioning. User can override to option A (3-second cut) if cleaner edit preferred.

**Sub-finding — shared-conceptual-space scholars as error class:** Geissinger and Llewellyn-Jones both write about veil-as-social-regulation. The conceptual proximity is exactly what made the conflation plausible. Pattern generalizable: whenever a script's "X named this Y" claim involves a scholar working in a field with multiple cognate theorists, attribution requires its own check pass, not a quote-grounding inheritance.

### Finding 2 — Metadata file silently drifted from finished cut [MEDIUM-HIGH — caught before publish]

`YOUTUBE-METADATA.md` was authored pre-filming and never re-derived against the finished cut. Opus planning pass found four discrete drift points:

| Drift | Symptom | Cost if shipped |
|---|---|---|
| Title promise unfulfilled | Variant 3 promised "Three Medieval Scholars" — only Ibn al-Jawzi named in finished cut | Audience clicks a promise the video doesn't keep; CTR earns retention penalty |
| Dangling description fragment | "...required free women to —" (sentence cuts off mid-clause) | Broken sentence visible above the fold on mobile |
| Chapter timestamps from script estimates | 9 chapters ending at 7:52; actual SRT runs 11:26 | Every chapter wrong; user-facing nav broken throughout |
| Source list noise + omission | 4 scholars not load-bearing in finished cut still listed (Secunda, Reda/Amin, Laiou); 2 critical ones missing (Geissinger, Lerner) | Signals research breadth that doesn't match what was watched; missing scholars are exactly the ones load-bearing for thesis |

**Root cause:** No discrete post-rough-cut step re-derives metadata from SRT + finished-cut reality. The file carries forward from pre-filming research and rots silently until publish-day forces a look.

**Extension of `[Earn-Your-Inclusion Test]` (memory rule):** the earned-inclusion principle currently applies to script-body facts. This session reveals it must also apply at metadata level:
- Every scholar in description source list must appear in finished cut (else cut)
- Every title promise must be deliverable in finished cut (else rewrite)
- Every chapter timestamp must derive from actual SRT (else regenerate)

**All four drifts corrected this session** — see `06-METADATA-EXECUTION-LOG.md` for the diff.

### Finding 3 — `/fix` and `/verify-attributions` are different tools [MEDIUM — exposed gap, no tool yet]

`/fix` ran post-filming on the SRT and caught 13 transcription errors (Whisper artifacts): "Gast/Cast", "must fail/veil" recurring, "Bintalha/bint Talha", "Gita Palahani/Kitab al-Aghani", "prophet's vice/wives", "all three women/all free women", "rights laws/writes laws", "dresses national/dress as national", "law and virtue/Law on Virtue", "was in the stable/was not a stable", "ta'arut/ta'arrud". All transcription-level corrections.

`/fix` did **not** catch the Lloyd Jones / Geissinger error — and that's correct behavior. The /fix mandate is "match what was said in the video, word-for-word." What the user said was "Lloyd Jones"; Whisper transcribed it correctly. **The script was wrong; the delivery was faithful to the wrong script; the transcription was faithful to the delivery.**

Two distinct post-filming audits, currently collapsed into one:
- `/fix` — transcription fidelity (Whisper vs spoken audio)
- `/verify-attributions` (proposed) — fact fidelity (spoken/scripted claims vs primary sources)

The 04-ROUGH-CUT-POSTMORTEM Finding 6b case (Aisha bint Talha "granddaughter of Abu Bakr" — inherited claim never round-tripped) is the same class of error caught only by user-vigilance at the take. Without a dedicated tool, this class only gets caught when a human notices.

`52-hijab-production-state.md` (the per-project memory snapshot) was last substantively updated 2026-05-14 mid-grill. By this session it references:

The snapshot was correct at one moment and the production reality moved past it. No automatic refresh trigger at lifecycle transitions. Snapshots survive across phases as frozen artifacts that get read by future-Claude as if current — every other drift compounds when the snapshot itself is stale.

Not strictly a verification failure but a *source-of-truth drift* failure that amplifies all other findings because the snapshot is often the first thing a continuing session reads.

### Finding 5 — Postmortem methodology bias extends to attribution dimension [META]

`04-ROUGH-CUT-POSTMORTEM.md` Finding 6 already logged: "default assumption that SCRIPT.md is correct and delivery deviates is wrong about 1 delta in 15."

This session extends the methodology bias to a second dimension:

> **Default assumption that "verified quote" = "verified attribution" is wrong when scholar X is quoting/borrowing/paraphrasing scholar Y.**

Both biases share a root pattern: treating a previously-validated artifact (SCRIPT.md, NotebookLM-verified quote) as authoritative on dimensions it was never validated on. The script was validated for quote content, not for attribution chain. The snapshot was validated at filming time, not at metadata time.

**Generalizable principle to log:** validated-at-time-T artifacts must be re-stamped with what they were validated *for*, so future readers don't inherit them as universally authoritative.

## 3. Workflow improvements (proposed P7–P10, ranked by leverage)

Original P1–P6 in `06-VERIFICATION-WORKFLOW-POSTMORTEM.md` covered the §V card chain. These four extend to this session's discoveries.

### P7. Attribution-check pass distinct from quote-grounding [HIGH]

For every `X named this Y` / `X coined Y` / `X termed it Y` formulation in a Format C script, require a discrete check: open the primary and confirm X is the *originator* of Y, not merely a *user* of Y. Build into Rule 42 as a sub-rule. Especially required when X works in a field with multiple cognate theorists.

Trigger phrases to audit before DRAFT-LOCKED: "named", "coined", "termed", "called this", "labelled this", "the [Name] regime/system/framework/principle/term".

Implementation: cheap grep-and-flag pass in `structure-checker-v2.md`.

**Would have prevented Finding 1.**

### P8. Post-rough-cut metadata re-derivation [HIGH]

After rough cut exists, run a discrete `/refresh-metadata` step (or extend `/editing-guide`) that:
- Re-derives chapter timestamps from actual SRT structural pivots
- Audits description source list against scholars actually named in finished cut (cut absent, add load-bearing)
- Audits title promises against finished-cut deliverables (flag unfulfilled)
- Greps description body for dangling sentences / em-dashes / mid-clause cuts

Output: a `YOUTUBE-METADATA-DRIFT.md` diff the user accepts or overrides before publish.

**Would have prevented all four drifts in Finding 2.**

### P9. `/verify-attributions` as sister tool to `/fix` [MEDIUM]

Two post-filming audits with distinct mandates, currently collapsed:
- `/fix` audits SRT vs delivered audio (transcription fidelity)
- `/verify-attributions` audits SCRIPT.md vs NotebookLM grounding (fact fidelity, especially attributions)

Run as a pair pre-publish. Format C scripts cannot publish if `/verify-attributions` finds any `X named/coined/termed Y` claim without an `[ATTRIBUTION-VERIFIED]` annotation. Recommendation-only for Format A/B.

**Sister-tool to Finding 3.**

### P10. Snapshot lifecycle-transition refresh [LOWER, cheap]

When `/reconcile` moves a project across a lifecycle boundary (`_IN_PRODUCTION/` → `_READY_TO_FILM/` → `_ARCHIVED/`), trigger an `AskUserQuestion`: *"Memory snapshot is from [date], predates [transition]. Refresh inline, mark stale, or accept?"* Prevents stale snapshots from drifting through the production lifecycle as authoritative reads.

Cheap wire-in to existing `/reconcile` flow.

**Closes Finding 4.**
