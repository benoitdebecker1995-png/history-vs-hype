## 7. The deliverable that outlives this video

Alongside Round 2 and Round 3, maintain **`_research/VOICE-RULES-DERIVED-2026-07-22.md`**.

Every time he picks between two lines, write the rule the pick implies — in the form the profile uses, which is *an approved line, a rejected counter-example, and the discriminator between them*:

```
### <what this governs>
✅ <the line he chose, verbatim>
❌ <the line he rejected, verbatim>
Discriminator: <what makes the difference — the thing that lets you predict his next pick>
Scope: <does this hold everywhere, or only in this position / this kind of beat?>
```

Two disciplines on this, both learned the hard way here:

- **A rule derived from one line is worth almost nothing until it is tested somewhere he did not flag.** The standing instruction on this project is *derive the rule, then apply it where he didn't flag it* — a reworded line is a rule, not a patch. So for each rule, name one *other* place in the script it should apply, and apply it. If it produces a line he then rejects, the rule was wrong and that is a more valuable finding than the original pick.
- **Do not generalize from n=1 to canon.** I did exactly that on this project and wrote a false finding into the profile. Mark each rule `CONFIRMED` (he picked it twice, or it survived a test elsewhere) or `HYPOTHESIS` (one pick). The profile only accepts CONFIRMED.

At the end of the session this file gets folded into `.claude/REFERENCE/VOICE-PROFILE.md` and `channel-data/calibration/CALIBRATION-CORPUS.md`, and the working method gets distilled into a reusable command. That is the "invest once, replicate" payoff, and it is the actual point.
